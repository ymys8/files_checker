# Files Checker

Набор консольных приложений для проверки файлов на наличие вредоносных паттернов. Система состоит из TCP-сервера, клиента для отправки файлов на проверку и утилиты для просмотра статистики обнаруженных угроз.

Сервер принимает файлы от клиентов, проверяет их содержимое на совпадение с заданными паттернами и возвращает результат. Для каждого клиента создаётся отдельный процесс. Статистика обнаружений хранится в разделяемой памяти и доступна утилите через именованный канал (FIFO).

## Требования

- ОС Linux
- Компилятор с поддержкой C++17 (GCC 7+ / Clang 5+)
- CMake 3.24+
- Git (для загрузки зависимостей через FetchContent)

Сторонние зависимости подтягиваются автоматически при сборке:
- [nlohmann/json](https://github.com/nlohmann/json) v3.11.3 — парсинг конфигурационного файла
- [Google Test](https://github.com/google/googletest) v1.14.0 — unit-тесты

## Сборка

```bash
mkdir build && cd build
cmake ..
cmake --build .
```

После сборки в директории build/ появятся три исполняемых файла: client, server, util, а также тестовые бинарники test_client и test_server.

## Запуск

### Сервер

```bash
./server --config <путь_к_конфигу> --port <порт>
```

Пример:

```bash
./server --config ../test_data/config.json --port 12345
```

Конфигурационный файл — JSON со списком паттернов для поиска:

```json
{
    "patterns": [
        "rm -rf /",
        "eval(base64_decode",
        "DROP TABLE",
        "<script>alert",
        "EICAR-STANDARD-ANTIVIRUS-TEST-FILE"
    ]
}
```

Для корректного завершения сервера отправьте сигнал SIGINT (Ctrl+C) или SIGTERM. Сервер дождётся завершения всех дочерних процессов и закроет соединения.

### Клиент

```bash
./client --file <путь_к_файлу> --port <порт>
```

Пример:

```bash
./client --file ../test_data/infected.txt --port 12345
```

Возможные ответы клиенту:

- `FILE IS CLEAN` — вредоносных паттернов не обнаружено.
- `INFECTED: <паттерн>(кол-во) ...` — найдены совпадения с указанием количества.

### Утилита статистики

```bash
./util
```

Утилита подключается к серверу через FIFO и выводит текущую статистику: количество проверенных файлов и число обнаружений каждого паттерна. Сервер должен быть запущен в момент вызова утилиты.

## Запуск тестов

```bash
cd build
ctest --output-on-failure
```

Или напрямую:

```bash
./test_client
./test_server
```

## Структура проекта

- **client/** — Исходники клиента. Клиент парсит аргументы командной строки, читает файл, отправляет его содержимое на сервер и выводит результат проверки.

- **server/** — Исходники сервера. Сервер читает конфигурацию паттернов, слушает входящие подключения, создаёт дочерний процесс на каждого клиента, проверяет файл и ведёт статистику.

- **util/** — утилита для отображения статистики. Читает данные из FIFO и выводит их на консоль.

- **common/** — константы и структуры, которые используются несколькими программами. Используется сервером и утилитой.

- **tests/** — unit-тесты на Google Test для клиента и сервера.

- **test_data/** — готовые тестовые файлы: конфиг (`config.json`), и файлы для проверки.

- **third_party/** — CMake-конфигурация для загрузки внешних зависимостей через FetchContent.
